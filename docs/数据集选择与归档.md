# 数据集选择与归档

本项目不把“沿用旧目录中的全部数据”作为选择标准。每个数据集必须承担清楚的实验角色，
并在运行前固定来源、处理规则和文件指纹。主表统一使用八个数据集和同一组分位点；数据集
选择先依据公开来源、结构层次、属性类型和可复现性，再用预注册的 pilot 网格排除几乎不能
形成跨方法比较、或输出结构缺乏辨识度的候选。pilot 只决定数据集是否适合承担主表角色，
不能用于为单个数据集挑选更有利的阈值。

## 1. 数据角色

自然向量组用于验证语义约束确实作用于真实属性。主表固定使用 FB15K-237、WN18RR 和
ogbn-arxiv。FB15K-237 呈现 StrSub 的中低阈值区间和 MonoSemMCE 的高阈值区间；
ogbn-arxiv 同时支持分位点、嵌套规模和线程实验；WN18RR 提供小规模、三种语义方法均能
完成的完整对照。DBLP 完整图在 q99 pilot 中对 StrSub 和 MonoSemMCE 均达到 180 秒筛选
界限，只保留为诊断记录；Products 不进入当前主表。它们的原始数据与 pilot 记录不删除。

受控结构组保留公开真实图结构，但使用可复现生成的单位向量。它们只隔离结构密度、退化
度和极大团分布的影响，不用于声称结果具有自然语义。当前主表冻结 email-Enron、
sc-nasasrb、sc-pkustk11、sc-pwtk 和 sc-ldoor。生成器使用 PCG64、固定的逐数据集种子和
256 维独立 `Uniform[-1,1)` 坐标，共享加载器再做 L2 归一化。生成脚本、种子、图与向量
SHA-256 分别进入结构向量归档；旧的无固定种子向量完整保留在 `no-use`，不再用于正式结果。

原始本地结构图没有被删除。sc-ldoor 曾因当前实验重建时漏测而未进入旧表，并非算法表现
不合格；统一网格补测后，它在 StrSub 的 q20/q99 和 MonoSemMCE 的 q80/q99 均完成，因此
恢复到主表。sc-pwtk 此前只缺固定种子向量，补齐可复现向量后也通过同一筛选。sc-msdoor
与 sc-ldoor 来源和结构特征高度重合，保留较大、层次更清楚的 sc-ldoor。soc-buzznet 的
StrSub 在 q5/q20 内存耗尽、在 q50/q80/q99 达到 pilot 上限；soc-digg 和 tech-as-skitter
主要形成 MonoSemMCE 的极高阈值单方法压力结果，因此不再承担主表角色。com-Amazon 的
结果有 73% 为二元或三元团，SemBK 的固定开销反而更低，缺少论文核心机制所需的区分度。
ca-dblp-2012 在统一网格上只有 StrSub q20 完成，也不进入主表。AMiner 不作为候选。

## 2. ogbn-arxiv 的加入

ogbn-arxiv 来自 Open Graph Benchmark 官方发布页
<https://ogb.stanford.edu/docs/nodeprop/#ogbn-arxiv>。官方数据包含 169,343 篇论文、
1,166,243 条有向引用记录，以及由标题和摘要词向量平均得到的 128 维节点特征，许可为
ODC-BY。原始包从
<https://snap.stanford.edu/ogb/data/nodeproppred/arxiv.zip> 下载。

`scripts/import_ogbn_arxiv.py` 丢弃自环，将引用边无向化并去重，按端点 ID 排序；官方
float32 特征值不做降维或重新训练，仅转换为项目加载器需要的逐行 float64 二进制。算法
仍通过共享加载流程做 L2 归一化。原包、输出图和输出向量的 SHA-256、许可、来源 URL、
边去重数量和转换规则保存在 `dataset/provenance/ogbn-arxiv.json`。数据文件由 Git ignore，
转换脚本和数据目录表进入版本控制。

## 3. 归档层级

原始运行文件保存在 `experiment-output/<run>/`，包括任务 JSON、stdout、stderr、程序日志
和可选的完整结果集合。这一层不进入 Git，也不允许手工覆盖。每次重跑使用新的 attempt
编号并记录原因。

`experiments/archive/<run>.manifest.json` 是可进 Git 的证据清单。归档器重新验证计划哈希、
源码指纹、可执行文件哈希、运行前输入哈希、状态、结果计数和所有产物哈希。输入指纹覆盖
图文件、向量二进制，或向量索引及索引列出的每个分块。归档清单只保存仓库相对路径。

早期运行发生在输入指纹功能加入之前，清单必须标为 `legacy_post_run_snapshot`，不能写成
运行时验证；在标准源码冻结前编译的历史二进制同理标为 `legacy_mismatch`。新的正式实验
缺少运行时输入哈希、源码不匹配、计划被修改或集合比较失败时，归档器默认拒绝写清单。

`experiments/summaries/<run>.summary.json` 只从上述 manifest 计算。重复运行只有在总数和
各 size 层一致时才汇总；raw 计时报告中位数和范围，stats 运行不生成主表时间。论文数字
必须能够沿 summary、manifest、任务 JSON、原始日志逐层追溯。
